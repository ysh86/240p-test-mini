# 240p Test Suite mini（240pee）の FDS 移植まとめ

pinobatch の 240p-test-mini（NES 版「240pee」）を、ファミコンディスクシステム
（FDS）で動くようにした移植です。正規の FDS の範囲内で作っています：

- 標準形式の `.fds` イメージ1ファイル（片面1枚、65,500 バイト）
- カスタムファームウェア不要（FDSKey の純正ファームウェアで起動する）
- 任天堂のデータ（KYODAKU ファイル等）は含まない
- 実行時のバンク切替はすべて BIOS の LoadFiles（$E1F8）経由

成果物：`nes/240pee-fds.fds`（65,516 バイト = ヘッダ 16 + 片面 65,500、
MD5 `3da6b7e5a903f81256aa75a844c03740`）

## ベースとメモリ配置

ベースは SGROM（MMC1 + CHR RAM）版です。CHR RAM 8KB 前提が FDS と
一致し、縦ミラーリングは起動時に $4025 で設定できるためです。
カートリッジの PRG を PRG RAM に
折り畳みます（`nes/fds.cfg`）：

- **切替ウィンドウ $6000–$9FFF**（16KB）：元の $8000 バンク×3 をここへ読む
- **固定バンク $A000–$DFFF**（16KB）：元の固定バンク $C000–$FFFF。
  最上位 10 バイト（$DFF6–$DFFF）は BIOS のベクタテーブル用に空ける
- DMC は $C000 以上でしかサンプルを再生できないため、固定バンク内では
  LIBDATA/LIBCODE/CODE を先に置き、DMC セグメントを $C000 以後に配置する

## バンク切替 = BIOS ファイルロード

`src/mmc1.s` のマッパー抽象化と同一の契約（`mmc_bank_a`、`unpb53_gate`、
`rtl`、`load_sb53_file`、`load_iu53_file`、`unpb53_file`、
`rf_load_layout`）を保ったまま、バックエンドだけを `src/fds.s` に
差し替えました。共有コードは変更していません。

- 論理バンク→ファイル ID の対応：バンク 0 → ID 4、1 → ID 5、2 → ID 1
  （バンク 2 はブートファイル兼用のため ID が若い）
- `cur_bank` で常駐バンクをキャッシュし、同じバンクへの切替は無操作
- LoadFiles の作法：FDS タイマ IRQ／APU フレーム IRQ／DMC IRQ を止め、
  PPUCTRL ミラー $FF に $00 を書いて VINTWait（$E1B2）で NMI を切り
  VRAM インクリメント +1 を保証し、1 エントリのファイルリストで
  LoadFiles（$E1F8）を呼ぶ。ディスク ID はブート時と同じく
  チェックスキップ値を使う
- 復帰時は描画用 PPUCTRL（$80、NMI 有効）を $FF と $2000 に書き戻す。
  X/Y レジスタは呼び出し側のために保存する
- ロードがエラーになった場合は約1秒待って再試行する（上限16回）。
  失敗時はキャッシュを無効化（$FF）して次の要求で読み直す

## ディスクレイアウト（物理順）

| # | 名前 | ID | ロード先 | サイズ | 用途 |
|---|---|---|---|---|---|
| 0 | BANK2 | 1 | $6000 | 15,928 B | メインコード＋ヘルプ（ブート兼ランタイム） |
| 1 | BANK0 | 4 | $6000 | 16,265 B | PB53 圧縮グラフィック（ランタイム） |
| 2 | BANK1 | 5 | $6000 | 5,195 B | ゲートデータ（ランタイム） |
| 3 | FIXED | 0 | $A000 | 15,572 B | 固定バンク（ブート） |
| 4 | VECTORS | 2 | $DFF6 | 10 B | BIOS ベクタテーブル（ブート） |
| 5 | -BYPASS- | 3 | $2000 | 1 B | $90：NMI 有効化（ブート） |
| 6 | PAD | 6 | $6000 | 2,048 B | ダミー（読み飛ばし用、後述） |
| 7 | TAIL | 48 | $6000 | 256 B | 末尾のブロック列を整形式に保つダミー |

boot read file code = 3 で、ID 0–3 のファイルだけがブート時に
ロードされます。ブロック CRC はイメージに格納しません（.fds の通常形）。

## ブートシーケンス（KYODAKU 無しの homebrew 起動方法）

FDS の BIOS は通常、ブートロード後に VRAM の許諾文字列を照合し、
一致しなければ起動を拒否します（いわゆる KYODAKU チェック）。
この移植では、許諾データを同梱せず、**照合が始まる前に最初の
vblank NMI で制御を奪う**ことで起動します。手順は次のとおりです。

1. BIOS がディスク情報ブロックとファイル数ブロックを読み、boot code
   以下の ID を持つファイルを物理順にロードします。本イメージでは
   BANK2（$6000）、FIXED（$A000）、VECTORS（$DFF6）、-BYPASS-（$2000）
   の順です（BANK0/BANK1 はブート対象外で、実行時に LoadFiles で読む）。
2. VECTORS が $DFF6 の BIOS ベクタテーブルを自前ハンドラで埋めます：
   NMI #1/#2 = `nmi_handler`、NMI #3 = `fds_boot`、
   RESET = `fds_boot`、IRQ = `irq_handler`。
3. -BYPASS- は $2000（PPUCTRL）への1バイト `$90` で、NMI 生成を
   有効化します。ブートファイルの最後に置くことが要点です。
4. BIOS は引き続き、ブート対象外ファイル（PAD）の読み飛ばしに
   かかっています。その最中に最初の vblank が来て NMI が発生し、
   BIOS の NMI ディスパッチャが NMI #3 ベクタ（$DFFA）経由で
   `fds_boot` に入ります。承認チェックはまだ実行されていないため、
   KYODAKU ファイルなしで起動が成立します。PAD のダミーファイルで
   読み飛ばし時間（約0.2秒）を稼ぐのがこの方式の肝で、-BYPASS- を
   片面の最後に置くと BIOS が先にチェックを終えてしまいます。
5. `fds_boot` は直接入口として初期化します：
   - NMI を切り（$2000 = $00）、$0101 = $C0（ゲームモード）を設定
   - リセットディスパッチフラグ $0102 = $35／$0103 = $AC を自前で立てる。
     通常は BIOS がブート完了後に設定しますが、バイパスで割り込んだ
     ため未設定であり、これがないとソフトリセット時に正しく
     ゲームへ戻れません
   - ドライブを休止状態にして、ネームテーブル配置を縦ミラーリングに
     設定する。BIOS のリセットスタブが使う休止値を bit3 = 0 にした
     $26 を $FA／$4025 に書きます（後述）。コールド時はブートの
     読み飛ばしが中断された状態のため、この書き込みでソフトリセット
     時と同じドライブ状態から始めます
   - NMI スロット3つすべてを `nmi_handler` に付け替え、
     `cur_bank` = 2（ブートで読み込み済み）として `reset_handler` へ
6. ソフトリセット時も RESET ベクタが `fds_boot` を指し、フラグも
   設定済みのため同じ入口を通ります。PRG RAM はリセットで消えない
   のでバンク2は常駐したままです。

## FDS 固有の制約：$0100 ページ

FDS では $0100–$0103 は BIOS のシステムバイトです（$0100 = NMI
振り分けモード、$0101 = 転送状態、$0102/$0103 = リセット
ディスパッチフラグ）。本スイートはカートリッジ前提で $0100 ページを
スクラッチバッファに使うため、FDS ビルドでのみ `.ifdef USE_FDS` で
$0700 ページ（BSS 終端 $063C のため空き）へ移設しました。対象は
`unpb53.s`（PB53_outbuf）、`vwf_draw.s`（lineImgBuf）、`rectfill.s`、
`kiki.s`、`mdfourier.s`、`padstest.s` の6ファイルで、makefile は
これらだけ `-DUSE_FDS=1` の別オブジェクトを FDS リンクに使います。
カートリッジ版には無条件の変更は入っていません（`USE_FDS` 未定義時は
従来どおりにアセンブルされます。作業ツリーでの SGROM 版再ビルドで
従来イメージとバイト一致を確認）。

## FDS 固有の制約：ゼロページと $4025

ゼロページにも BIOS の領域があります：$00–$0F はディスクルーチンの
作業域、$F1–$FF はコントローラ状態と書き込み専用レジスタのミラー群
（$F9 = $4026、$FA = $4025、$FB = $4016、$FC/$FD = $2005、
$FE = $2001、$FF = $2000）。本スイート自身の ZP 使用は $10–$4C だけ
ですが、起動時の ZP 全消去が BIOS の種値を消してしまうため、FDS
ビルドでは次を行います：

- `fds.cfg` の ZP 領域を $10–$F0 に制限し、$F1 以降へ伸びたら
  リンクエラーにする
- `src/init.s` の ZP クリアは `USE_FDS` 時に $10–$F0 のみ対象とし、
  BIOS の状態をリセットからゲームまでそのまま保持する
- $FF は共有ミラーとして作法どおり使う（LoadFiles 前に転送用の
  値を置き、復帰時に描画用 $80 を戻す）。$FE を含む他のミラーと
  $F1–$FD には一切触らない

$4025（ディスク制御）については、モーターの停止／開始の操作は
しません。市販タイトル（スーパーマリオブラザーズ2）の実コードを
調査したところ、$4025 への書き込みは起動時の1回のみで、ゲーム中に
モーターを止めたり回したりはせず、LoadFiles は前処理なしで呼ばれて
いました。本移植の起動時の書き込みは、BIOS のリセットスタブが
ソフトリセット時に書く休止値 $2E の bit3（ネームテーブル配置）だけを
0 にした $26 で、縦ミラーリングの設定と、コールド時に割り込んだ
ブートで流れ続けているドライブを休止状態に戻すことを兼ねます。
モーターの開始は LoadFiles 自身が行います。LoadFiles が $FA から
導出する $4025 の値には bit3 が含まれるため、配置の設定は以後の
ディスクアクセスでも保持されます。

## FDS 固有の制約：ゲート呼び出しのコスト

カートリッジ版のゲート（PB53 データのバンク切替）はレジスタ書き込み
だけで済みますが、FDS 版では1回の往復がディスクロード2回分に
なります。Drop Shadow テストはタイル展開ループの中でブロック
（4タイル）ごとにゲートを呼ぶ作りで、そのままでは入口だけで
28往復のロードがかかるうえ、ループカウンタが BIOS の作業域
$00–$0E 内（$02）にあるため、実 BIOS の LoadFiles にカウンタを
書き換えられて終了も保証されません。FDS ビルドではこのループを
1回のゲートセッションの中で実行します（`shadowsprite.s` の
`USE_FDS` 分岐と `fds.s` の `unpb53_shadow_batch`）。ブロック数は
レジスタでも $02 でもロードを越えられない（LoadFiles はレジスタも
書き換えます）ため、BSS の変数でセッション内に受け渡します。

## ビルド

```sh
cd nes
make 240pee-fds.fds   # cc65 が必要
```

ld65（`fds.cfg`）が bank0/bank1/bank2/fixed の各バイナリを出し、
`tools/make_fds_image.py` がリンクマップから実使用端でトリムして
.fds を組み立てます。

## 検証

- py65 シミュレーションで無改造 SGROM 版と FDS 版に同じ入力を与え、
  安定状態 11 ステージで VRAM（CHR＋ネームテーブル）とパレットが
  バイト完全一致。サウンドテスト画面とビープ／オーディオシンクの
  APU 書き込み列も一致
- FCEUX 2.6.5 ＋ 実物 BIOS ダンプで、コールドブート→タイトル→
  メインメニュー→バンク切替を伴うテスト画面→復帰、ソフトリセット
  後のタイトル復帰、ロード途中のリセットからの復帰を確認
- ロード時間：LoadFiles はヘッドの現在位置から前方へ走査するため、
  バンク切替を伴う画面遷移には1回あたり数秒〜6秒強のポーズが入る
  （コールドブート→メニューは起動時ロードを含め約45秒）。
  これは媒体の特性どおりの挙動
- FCEUX で Hill Zone Scroll／Vertical Scroll の両テストを開き、
  ミラーリング設定の有無で表示が変わることを確認（設定なしでは
  Vertical Scroll の流入部分がグレーになり、Hill Zone の滝が
  表示されません）
- 実機（ファミコン＋RAM アダプタ＋FDSKey、純正ファームウェア相当）
  で動作確認済み（2026-10-27〜28）：起動→メニュー→複数のバンク切替
  テスト画面が正常動作。ロードのポーズも実機で同様。スクロール系
  テストのミラーリング修正、コールドブート時のドライブ休止
  書き込み、Drop Shadow のゲートバッチ化は、いずれも実機で
  確認済み。Drop Shadow で Select を押して表示するキャラクタの
  タイルが欠ける問題（バッチのブロック数が入口のロードで
  書き換えられていた）への修正は、実機での最終確認待ち

## 制限・注意

- NES 周辺機器を使うテスト（ザッパー、Four Score、Power Pad、
  SNES マウス等）はファミコンでは試せません。スイート自体の動作には
  影響しません
- ディスクへの書き込みは行いません（読み込み専用）
- 既知の問題：Hill Zone Scroll テストから B ボタンでメニューに
  戻る際、実機ではハングする場合があります（読み込みが止まり、
  画面が崩れたまま固まります）。エミュレータ（FCEUX、Mesen）では
  再現せず、実機のディスクタイミングに起因するものとみられます。
  リセットを押せばメニューに戻ります
